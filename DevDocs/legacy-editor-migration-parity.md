# Legacy Editor migration parity

## Purpose and scope

This document freezes current behavior of `legacy-editor-claude-design-template` as migration evidence. It describes the unchanged Chromium baseline; it does not define the future architecture or promise that legacy behavior is desirable. The legacy source remains the authority when this record and implementation disagree.

The automated suite serves the original files through Vite and intercepts their three pinned unpkg requests with byte-equivalent local npm packages. This keeps the test runtime deterministic and offline after dependency installation without modifying the legacy page.

The ReactDOM 18 package is consumed only as a UMD test asset; it is not imported into the React 19 workspace. The narrowly scoped pnpm peer rule records that asset-only exception and must be removed with the legacy harness.

## Legacy constraints and manual-only checks

| Constraint                  | Current source fact                                                                                                                                                                                                                                                                                                                              | Migration criterion                                                                                                                                                                                      |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Deprecated editing APIs     | `app.jsx:65-161` depends on `document.execCommand`, `queryCommandState`, and `queryCommandValue`, plus Range-based wrapping. Output and command support are browser-dependent.                                                                                                                                                                   | Migration may intentionally replace these APIs, but Chromium editing, formatting state, undo/redo, selection, paste, and generated markup must be compared with explicit fixtures before legacy removal. |
| Native browser surfaces     | Print calls `window.print()` (`app.jsx:84,189`); link insertion uses `prompt()` (`app.jsx:153`). Ctrl/Cmd+S only prevents the browser default.                                                                                                                                                                                                   | Print preview/output, prompt cancellation/acceptance, and save-key handling require an agreed manual/browser automation strategy before cutover. No persistence behavior should be inferred for Save.    |
| Accessibility gaps          | Ribbon tabs are buttons without tablist/tab semantics (`ribbon.jsx:17-29`). Menus and Backstage items are clickable divs (`primitives.jsx:63-74`; `doc-status.jsx:83-90`). overlays lack `role="dialog"`, accessible names, focus traps, focus restoration, and Escape handling (`doc-status.jsx:117-169`). The document has no accessible name. | Future UI must meet its own accessibility contract. These gaps are documented baselines, not parity targets; migration cannot claim accessibility verification from visual/Chromium behavior alone.      |
| Responsive/browser coverage | `styles.css` uses fixed 268 px/250 px panels and an 816×1056 document, horizontal ribbon overflow, WebKit scrollbar rules, and no media queries.                                                                                                                                                                                                 | Narrow layouts, non-Chromium engines, zoomed browser UI, touch, high contrast, reduced motion, screen readers, and keyboard-only navigation remain unqualified until the later support-matrix phase.     |
| Runtime delivery            | The page uses development UMD React, in-browser Babel compilation, ordered globals, and remote URLs with SRI (`index.html:7-21`).                                                                                                                                                                                                                | Characterization intercepts exact pinned packages locally. Production migration must not infer bundling, module, CSP, offline, or dependency-loading guarantees from this legacy runtime.                |
| Static prototype actions    | Numerous ribbon/menu controls intentionally have empty handlers or explanatory placeholder content.                                                                                                                                                                                                                                              | Only behavior covered above is frozen. A visible control is not evidence of an implemented command; future requirements need an explicit product decision.                                               |

## Migration gate

Before removing the legacy reference, the replacement Editor workspace must pass the automated characterization scenarios or have an approved, documented divergence for each failed parity item. Screenshot changes require explicit baseline regeneration and review. Manual-only items require recorded evidence against the agreed browser/accessibility matrix; undocumented differences are not accepted as parity.
